Рабочая среда специалиста

Б2доклад с демонстрацией30 мин

Среда — это данные, модели, агенты, система записи, права и аудит. А не один чат. Чат — инструмент, среда — процесс.хук

0–8′ Анатомия среды

  • Данные. То, на чём работает модель и на чём проверяется результат.
    чек Данные для среды

    Нужно: источник данных (CRM, звонки, документы) + владелец качества + разметка «хорошо/плохо». Без этого — чат, не среда.

  • Модели. Не одна, а набор под задачи.
    подход Набор, не «лучшая модель»

    Одна для классификации (быстрая, дешёвая), другая для генерации (качественная), третья для анализа. Меняй модель за день, если привязка — к процессу, не к модели.

  • Агенты. Сценарии с действиями, а не только с ответами.
    разница Агент = чат с правами

    Агент имеет права (создать задачу, записать в CRM), логи и эскалацию. Чат — только ответ. Поэтому среда — это агенты в процессе, не чаты.

  • Система записи. CRM, ERP, трекер — то, где остаётся результат.
    критерий Система записи — тест

    Тест: найди результат сценария по ID через месяц. Нашёл — есть система записи. Нет — среда = чат, не воспроизводится.

  • Права. Кто что может делать.
    правило Минимальные права

    Принцип наименьших привилегий: агент может только то, что нужно для этой задачи, не больше. Права — это ответственность.

  • Аудит. Кто что сделал и почему.
    лог Что логировать

    Кто запустил, что на входе, что сделал агент, кто проверил, какое решение. Без лога — нельзя разобрать ошибку и нельзя масштабировать.

схема Среда на 1 слайд

Схема: Данные → Модели/Агенты → Система записи → Права/Аудит → Метрики. В центре — человек (постановка, проверка, оркестрация).

8–18′ День команды + демо

  • Очередь задач: что пришло, что в работе, что готово.
    очередь Как выглядит

    Доска: «Входящие → Агент работает → На проверке → Готово → Разбор». Каждая задача с ID, входом, результатом, проверяющим.

  • Проверка: человек смотрит результат и фиксирует решение.
    процесс Проверка 2 мин

    Человек: 1) принял/вернул с правкой, 2) отметил причину ошибки (данные/промпт/процесс), 3) записал в лог. Без фиксации — повторяете ошибки.

  • Метрики: время цикла, доля автозадач, качество.
    метрики 3 метрики среды

    Время цикла (медиана), доля автозадач (без человека), качество (принято без переделки). Если среда не улучшает — она не нужна.

  • Демонстрация одного сценария от заявки до результата.
    демо Сценарий для демо

    Сценарий: лид с формы → обогащение → классификация → черновик ответа → проверка менеджером → запись в CRM → метрика. Покажи каждый шаг с логом.

    Демо — на грязных данных, не на идеальных. Идеальные данные — обман.

18–24′ Роль человека

  • Постановка задачи.
    постановка Что ставить

    Человек ставит: цель, ограничения, метрику, что считать ошибкой. Модель — исполняет, не ставит.

  • Проверка результата.
    проверка Критерий проверки

    Человек проверяет не «нравится», а «соответствует ли критерию и можно ли объяснить почему». Если не можешь объяснить — не принимай.

  • Оркестрация: что отдать модели, что оставить себе.
    оркестрация Правило

    Отдай: часто, дёшево ошибиться, быстрая обратная связь. Оставь: высокая цена ошибки, нужны отношения/доверие.

24–30′ Метрики среды

Время цикла, доля автозадач, качество результата. Если среда не улучшает эти три — она не нужна, это просто ещё один чат.

Вопросы, к которым готовлюсь

С чего начать сборку среды?
С системы записи. Среда без неё — это чат, а не процесс. Сначала реши, куда записывается результат — потом всё остальное.
Не слишком ли дорого?
Дорого не собрать — дорого содержать зоопарк чатов без процесса. Каждый компонент считается отдельно, начни с одного сценария.
